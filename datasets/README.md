# Datasets

**This project consumes no external dataset.** Every input to every reported result
is generated deterministically from the team's assigned seed, so the complete data
provenance is the seed plus the generator source.

This file records that provenance rather than padding the directory with derived
copies of data that already lives elsewhere in the repository.

## Where the actual inputs live

| Input | Location | Generated by |
|---|---|---|
| Run parameters (node count, topology, seed, sweep points) | [`../configs/group1_week3_config.txt`](../configs/group1_week3_config.txt) | Assigned in Week 1 |
| Seeded traffic traces | [`../traces/`](../traces/) | `python/gen_datacenter_traffic.py` |
| C reference trace (cross-language check) | [`../results/raw/traffic_reference_c.csv`](../results/raw/) | `./dump_traffic 3000` |
| Topology adjacency | constructed at runtime | `topology_build_{ring,mesh,torus}()` |

## Workload provenance

Both traffic patterns are drawn from an explicit **xorshift64\*** engine seeded
through **SplitMix64**, not from `rand()`. This matters for reproducibility: the
stream is identical on every machine and every C library, and the Python generator
reproduces the C stream bit-for-bit from the same seed.

- **Seed:** 1301 (assigned to Group 1)
- **Uniform-random:** every node equally likely as destination, source excluded.
- **Hot-node-skewed:** 50% of packets aimed at a small "database" set. The hot set is
  *derived from the seed* rather than hard-coded —
  `hot[0] = seed mod N`, `hot[1] = (seed div N) mod N` — which for seed 1301 and
  N = 16 gives nodes **{5, 1}**.

Because the seed is team-specific, the traces and every downstream result are
specific to Group 1.

## Regenerating

```sh
python3 python/gen_datacenter_traffic.py                 # rewrites ../traces/
python3 python/gen_datacenter_traffic.py --summary       # destination statistics
```

The defaults reproduce the committed traces **byte-identically** (5000 packets per
pattern, seed 1301).

## Verifying the generators agree

The C simulator and the Python reference generator must produce the same stream, or
the analytical model would be describing different traffic from the simulation. This
is asserted on every pipeline run:

```sh
./dump_traffic 3000
python3 python/gen_datacenter_traffic.py --verify results/raw/traffic_reference_c.csv
```

Expected output:

```
 uniform: 3000/3000 destinations match the C generator
 hotnode: 3000/3000 destinations match the C generator
VERIFIED: the Python and C traffic generators are bit-for-bit identical.
```

## Trace format

`traces/traffic_{pattern}_seed1301.csv`, 5000 packets per pattern:

```
pattern,index,src,dst
uniform,0,0,11
uniform,1,1,14
```

`src` cycles over all nodes; `dst` is drawn from the pattern's destination
distribution and is never equal to `src`, so every packet travels at least one hop.
